# 1 INTRODUCTION

Software development increasingly uses Continuous Integration and Continuous Deployment (CI/CD) to automate testing, building, and deployment tasks (Shahin et al. 2017). GitHub Actions is one of the commonly used tools for automating these workflows (GitHub s.a.). CI/CD performance is important because slow or unusual pipeline behaviour can delay feedback and consequently the software deployment process (Ghaleb et al. 2019). Therefore, pipeline execution data should be analysed systematically to identify unusual behaviour and potential performance problems.
iSign is an attendance management system which was developed as a team project. The system uses GitHub Actions for its continuous integration and continuous deployment (CI/CD) workflow. This thesis focuses specifically on the frontend deployment workflow, in which the React application is built, the build files are transferred to the server, the deployed files are synchronised, and the deployment is verified.
The selected iSign workflow is already used for deployment, but its execution behaviour has not been systematically analysed using historical GitHub Actions data. Some runs or steps may be slower or behave unusually compared with other runs. Without evidence-based analysis, it is difficult to separate normal variation from behaviour that may indicate inefficiency. Therefore, a systematic analysis method is required before any decision is made about optimization.
The main purpose of this thesis is to analyse the selected iSign frontend CI/CD workflow and to develop and evaluate an AI-assisted Python-based analysis tool for this task. The tool uses execution data to identify unusual behaviour and possible inefficiencies in the workflow. The findings are then used to support the selection of one justified CI/CD optimization. Finally, the effect of that optimization is measured later in the study.
This thesis is a practical development task rather than only a theoretical study. The work includes collecting and processing historical CI/CD execution data from the selected iSign workflow. A simple statistical baseline is compared with Isolation Forest to investigate unusual behaviour before an optimization is chosen. Finally, one practical workflow improvement is implemented, and its performance is evaluated before and after implementation.
This thesis is limited to the selected iSign frontend GitHub Actions workflow. The rest of the iSign system and other environments or workflows are outside the main scope of the study. Isolation Forest is the only machine-learning method used for anomaly detection. The public FastAPI dataset is used only as supporting reference data for method development and evaluation. The actual optimization and the before-and-after measurements are carried out in iSign.
The iSign system already existed before this thesis, and previous practical-training work included application development, integration, testing, and documentation. Those earlier contributions form the starting point of this study and are not treated as results of the thesis. This thesis focuses on CI/CD data analysis, development of a Python-based analysis tool, comparison of the selected analysis methods, and the optimization and evaluation of the workflow.
The following research questions were defined based on the objective of the thesis:
1.What inefficient or unusual behaviour can be identified in the selected iSign frontend GitHub Actions workflow?

    2.How does Isolation Forest support the identification of unusual workflow behaviour compared with a simple statistical baseline method?

    3.What measurable effect does one evidence-based CI/CD optimization have on workflow duration and resource use, while maintaining the required build, test, and deployment quality?
